# 5.1 ทดสอบระบบ Authentication and Authorization (Frontend — SvelteKit)

เอกสารนี้ครอบคลุมหน้า **ลงทะเบียน Sales** (`/register`) และ **เข้าสู่ระบบ** (`/login`) บนแอป SvelteKit  
การลงทะเบียน **ผู้จัดการองค์กร** ทำผ่านเว็บ Laravel backend — ดู `flow-crm-backend/docs/test-cases-auth.md`

---

## 5.1.1 ทดลองการลงทะเบียน (Sales — `/register`)

ฟอร์มบังคับ: **ชื่อ–นามสกุล** (อย่างน้อยสองคำตามกฎเซิร์ฟเวอร์), **อีเมล**, **รหัสผ่าน**, **ยืนยันรหัสผ่าน**, **รหัสเชิญองค์กร**  
**ไม่มี** ฟิลด์เบอร์โทรหรืออัปโหลดรูปในหน้านี้

**ตารางที่ 5.1 — กรณีทดสอบการกรอกข้อมูลลงทะเบียน (TC 1)**

| กรณีทดสอบ | เงื่อนไขการทดสอบ | ผลการทดสอบที่คาดหวัง | หมายเหตุ |
|-----------|------------------|----------------------|----------|
| TC 1.1 | ไม่กรอกข้อมูลทั้งหมด แล้วกดส่ง | แสดงแจ้งเตือนให้กรอกข้อมูล (เบราว์เซอร์ / validation) | ฟิลด์ `required` |
| TC 1.2 | กรอกเฉพาะชื่อ–นามสกุล | ไม่ส่งสำเร็จ — แจ้งให้กรอกฟิลด์ที่เหลือ | |
| TC 1.3 | กรอกเฉพาะรหัสผ่านและยืนยัน | ไม่ส่งสำเร็จ — ต้องมีอีเมล / รหัสเชิญ / ชื่อ | |
| TC 1.4 | กรอกเฉพาะอีเมล | ไม่ส่งสำเร็จ — ต้องกรอกชื่อ รหัสผ่าน และรหัสเชิญ | *ไม่ใช่* “สำเร็จด้วยอีเมลอย่างเดียว” |
| TC 1.5 | กรอกครบยกเว้นรหัสเชิญ | ไม่สำเร็จ — แจ้งให้กรอกรหัสเชิญ | `invite_token` required |
| TC 1.6 | กรอกชื่อ + อีเมล (ไม่มีรหัสผ่าน) | ไม่สำเร็จ | |
| TC 1.7 | กรอกชื่อ + อีเมล + รหัสผ่านครบ แต่รหัสเชิญผิด/ไม่มีในระบบ | ส่งแล้วได้ข้อความ error จากเซิร์ฟเวอร์ | แสดงใน `form.message` |
| TC 1.8 | กรอกครบถ้วนและรหัสเชิญถูกต้อง | ลงทะเบียนสำเร็จ — redirect ไปหน้าที่ระบบกำหนด | เช่น pipeline / dashboard |

## 5.1.2 ทดลองการเข้าสู่ระบบ (`/login`)

ใช้ **อีเมล + รหัสผ่าน** (ไม่มีช่องชื่อผู้ใช้แยก — ใช้อีเมลเป็น username)

**ตารางที่ 5.2 — กรณีทดสอบการกรอกข้อมูลเข้าสู่ระบบ (TC 2)**

| กรณีทดสอบ | เงื่อนไขการทดสอบ | ผลการทดสอบที่คาดหวัง | หมายเหตุ |
|-----------|------------------|----------------------|----------|
| TC 2.1 | ไม่กรอกข้อมูลทั้งหมด | แสดงแจ้งเตือนให้กรอกข้อมูล | |
| TC 2.2 | กรอกเฉพาะอีเมล | แสดงแจ้งเตือนให้กรอกรหัสผ่าน | |
| TC 2.3 | กรอกเฉพาะรหัสผ่าน | แสดงแจ้งเตือนให้กรอกอีเมล | |
| TC 2.4 | กรอกอีเมลและรหัสผ่านถูกต้อง แล้วกด Sign In | เข้าสู่ระบบสำเร็จ — ไปหน้าหลักของแอป (เช่น pipeline) | Session cookie จาก Laravel |

### กรณีเพิ่มเติมที่ควรทดสอบ

| กรณีทดสอบ | เงื่อนไข | ผลที่คาดหวัง |
|-----------|----------|--------------|
| TC 2.5 | รหัสผ่านผิด | แสดงข้อความ error ไม่ redirect |
| TC 2.6 | บัญชีถูกปิดการใช้งาน (`is_active = false`) | แจ้งว่าบัญชี inactive | ตรงกับ backend |

---

*อัปเดตล่าสุด: สอดคล้องกับ `src/routes/register/+page.svelte` และ `src/routes/login/+page.svelte`.*
